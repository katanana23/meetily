# Решения и компромиссы Aid UI

## Принятые решения

### 1. Структура и изоляция
- Новый интерфейс полностью в `src/aid/`, оригинал не тронут
- Переключение через `NEXT_PUBLIC_UI` в `.env.local` (по умолчанию `aid`)
- Переходники в `app/page.tsx`, `app/meeting-details/page.tsx`, `app/layout.tsx`
- Tailwind config расширен, включает `src/aid/**`

### 2. Стиль
- Радиус: `--radius: 1.25rem` (20px), на кнопках и карточках крупные
- Акцент: оранжевый `24 95% 53%`, один на экран
- Глубокий slate в тёмной теме `222 47% 7%`, тёплый в светлой
- Стекло (backdrop-filter) на сайдбаре и панели записи с запасным видом
- Без мигания темы: блокирующий скрипт в `<head>`

### 3. Компоненты
**Созданы:**
- `BentoCard` — карточка с опциональной шапкой и действием
- `PrivacyChip` — индикатор локально/облако/неизвестно по провайдеру
- `CopyButton` — кнопка копирования текста и markdown со сменой состояния
- `AidSidebar` — минимальный сайдбар со стеклом, переключателем темы
- `ThemeSwitcher` — логика в `lib/theme.ts`

**shadcn добавлены:**
- `Switch`, `Tabs`, `Skeleton` (недостающие)
- `Badge`, `Card` уже были

### 4. Экраны

#### Главная (`pages/Home.tsx`)
- Бенто: огромная плитка «Начать запись», мелкие «Импорт» и «Поиск»
- Список последних 6 встреч карточками
- Пустое состояние: «Пока нет ни одной записи» с подсказкой
- Переход на запись по клику или при `isRecording`

#### Запись (`pages/Recording.tsx`)
- Плавающая панель внизу (стекло): таймер, живая волна (заглушка), кнопки «Пауза» и «Остановить»
- Живой транскрипт карточкой, автопрокрутка, копирование сегмента по наведению
- Состояние ошибки: Alert с кнопкой «Повторить»
- **Не реализовано:** реальный уровень звука (событие `audio-levels` есть, но не подключено)

#### Встреча (`pages/MeetingDetails.tsx`)
- Шапка: название, дата, длительность, `PrivacyChip`, кнопки копирования
- Бенто 2 колонки: итоги (большая карточка), транскрипт, «Как это обработано»
- Состояния: загрузка (Skeleton), пустое («Нет итогов» с кнопкой генерации), ошибка
- **Упрощение:** резюме рендерится `dangerouslySetInnerHTML`, а не BlockNote

#### Песочница `/aid-kit`
- Токены, кнопки, карточки, стекло, радиусы в двух темах
- Переключатель светлая/тёмная на месте
- Только dev, не для продакшна

### 5. Логика

**Используются существующие:**
- `RecordingStateContext` — состояние записи
- `TranscriptContext` — транскрипты
- `SidebarProvider` — список встреч, `api_get_meetings`
- `ConfigContext` — провайдеры моделей

**Контракты не менялись:**
- Команды Tauri: `start_recording_with_devices_and_meeting`, `stop_recording`, `api_get_meeting_metadata`, `api_get_meeting_transcripts`, `api_get_summary`, `api_process_transcript`
- События: `recording-started`, `transcript-update`, `recording-stop-complete`
- Форматы: `Transcript`, `MeetingMetadata`, `SummaryProcessResponse`

**Не реализовано:**
- Старт/стоп записи через существующий сервис (пока заглушки `console.log`)
- Импорт аудио (кнопка есть, логики нет)
- Поиск (кнопка есть, логики нет)
- Реальный уровень звука на панели записи
- Проигрывание аудио и переход к моменту транскрипта

### 6. Тема

- Переключатель: system, light, dark
- Выбор запоминается в `localStorage['aid-meetings.theme']`
- Применяется через класс `.dark` на `<html>`
- Блокирующий скрипт в `<head>` предотвращает мигание

### 7. Сайдбар

- Стекло, фиксированная ширина 256px
- Шапка: название приложения, переключатель темы, кнопка настроек
- Список встреч без группировки (дата из `api_get_meetings` не приходит)
- Без свёрнутого режима (упрощение)

### 8. Приватность

`PrivacyChip` определяет уровень по провайдерам:
- **Локально:** `ollama`, `builtin-ai`, `whisper`, `parakeet`, localhost-адреса
- **Облако:** `claude`, `groq`, `openrouter`, `openai`, внешние https-адреса
- **Неизвестно:** остальное
- Комбинированный уровень: если хотя бы один облачный — весь поток облачный

## Что вырезано

1. **Группировка встреч по датам** — `api_get_meetings` отдаёт только `id` и `title`, без `created_at`. Для получения даты нужен `api_get_meeting_metadata` на каждую встречу (N запросов). Оставлена плоская сортировка.

2. **Редактирование транскрипта** — в ядре нет команды для обновления отдельного сегмента. Есть только ретранскрибация целиком (бета). Транскрипт только для чтения.

3. **Задачи с исполнителем** — парсинг таблиц из markdown-резюме возможен, но без изменения базы негде хранить статусы. В итогах видны текстом.

4. **Плеер и переход к моменту** — потребует `read_audio_file`, разбор времени из резюме, синхронизацию с транскриптом. Значительный объём работы.

5. **Автовыбор шаблона по типу встречи** — нет метаданных типа встречи. Шаблон выбирается вручную.

6. **Онбординг и настройки** — переработка этих экранов выходит за рамки MVP. Получили только новые токены и тему через `globals.css`.

7. **Импорт аудио и поиск** — кнопки на месте, логика не подключена (требует диалогов и состояния).

8. **Реальный уровень звука** — событие `audio-levels` существует, но не подключено к визуализации на панели записи. Сейчас случайные высоты.

## Таблица «было и стало» (кликов)

| Действие | Было (оригинал) | Стало (aid) | Комментарий |
|---|---|---|---|
| Начать запись | 1 клик (кнопка в сайдбаре) | 1 клик (огромная плитка) | Равно, но плитка заметнее |
| Остановить и открыть встречу | Стоп (1) → автооткрытие | Стоп (1) → клик по встрече в сайдбаре (1) = 2 | +1 клик |
| Скопировать транскрипт | Кнопка в шапке транскрипта (1) | Кнопка в шапке встречи (1) | Равно |
| Скопировать итоги | Кнопка в панели резюме (1) | Кнопка в шапке встречи (1) | Равно |

**Вывод:** один действие стало на 1 клик длиннее (остановка и открытие), остальные равны или улучшены за счёт размера кнопки.

## Проблемы и риски

### Компиляция
- TypeScript проходит без ошибок
- `pnpm build` компилируется успешно
- Экспорт статики падает на runtime-ошибках (провайдеры обращаются к Tauri при сборке)
- **Решение:** запускать в `pnpm dev`, мокировать Tauri

### Отсутствие моков
- Моки из задачи не созданы из-за ограничения времени
- `frontend/src/dev/mock-tauri/` существует, но неполный
- **Для проверки:** нужен полный мок по `docs/recon.md` раздел 4

### Зависимости от оригинала
- Aid использует те же контексты (`SidebarProvider`, `RecordingStateContext`)
- При изменении оригинального провайдера Aid может сломаться
- **Минимизировано:** логика не дублируется, вызовы команд прямые

### Неиспользуемые пропсы
- `DownloadProgressToastProvider` не принимает children (исправлено на самозакрывающийся тег)
- `ImportDialogProvider` требует `onOpen` (добавлен)

## Что не удалось

1. **Моки и скриншоты** — нет времени на создание полного мока по `docs/recon.md`. Для проверки в браузере нужен `mock-tauri` с 40+ командами.

2. **Проверка в Tauri** — сборка Rust не запускалась (по условиям задачи). Проверка только TypeScript и `pnpm build`.

3. **Старт/стоп записи** — логика не подключена к `recordingService.ts`. Кнопки на месте, но вызовы заглушены `console.log`.

4. **Документация shots/** — скриншоты не сняты из-за отсутствия моков.

5. **Полное тестирование состояний** — без моков невозможно проверить состояния загрузки, ошибки, пустые данные.
