# Как работать подробно

Перенесено из CLAUDE.md: полные тексты разделов «Проект», «Границы», «Данные», «Стиль», «Как работать» и «Вольт». Краткая версия там.

## Проект
- Продукт **Shade**, основан на открытом Meetily (MIT, Zackriya Solutions): приватный ИИ-ассистент встреч, запись, транскрипция и итоги на компьютере пользователя. Прежние рабочие названия «Aid Meetings» и «ShadeNotes» больше нигде не используются.
- Десктоп на Tauri 2: ядро на Rust (`frontend/src-tauri`, чужое), интерфейс на Next.js 14 + React 18. Свой слой интерфейса в `frontend/src/shade/` (ветка `shade`, префиксы `shade-` в классах, `[shade]` в журнале, `shade.` в ключах хранилищ).
- Идентичность: `identifier` `io.github.katanana23.shade` (от него папка данных), папки данных ядра `APP_DATA_DIR_NAME = "Shade"` и `RECORDINGS_DIR_NAME = "Shade"` (`src-tauri/src/config.rs`), ключи `localStorage` с префиксом `shade.` (`shade.theme` и др.). Любая смена этих имён отрывает данные пользователя от приложения: делать её только вместе со скриптом переноса, как `scripts/migrate-from-aid.sh` (2026-11-14, переход с `io.github.katanana23.aid-meetings`). Репозиторий на GitHub `katanana23/shade`.
- Ветка `main` зеркалит оригинал, рабочая ветка `shade`. Подробнее: `docs/FORK.md`, `docs/isolation.md`, `docs/recon.md`.

## Границы
- `frontend/src-tauri` не менять. Исключение: строки идентичности в `config.rs` и `tauri.conf.json`, отдельным коммитом и по явной просьбе.
- Не менять имена и аргументы команд и событий Tauri, форматы данных, миграции, ключи `localStorage` и `IndexedDB`.
- Оригинальные файлы интерфейса не трогать. Допустимы тонкие переходники: `app/page.tsx`, `app/meeting-details/page.tsx`, `app/settings/page.tsx`, `app/layout.tsx`, `tailwind.config.js`. Оригиналы лежат рядом в `page-original.tsx`.
- `frontend/src/dev/mock-tauri` не менять без явной просьбы.
- `backend/` (Python/FastAPI) архив, не использовать.

## Данные и секреты
- В репозитории никаких реальных встреч, записей, ключей и личных данных. Фикстуры только вымышленные (`src/dev/mock-tauri`).
- Секреты не печатать и не коммитить.

## Стиль
- Отчёты и объяснения на русском; термин при первом упоминании объяснять одной фразой.
- Без длинных тире, кавычки-ёлочки в русском тексте.
- Тексты интерфейса короткие и конкретные: что случилось и что сделать.

## Заглушки
- Интерфейс разрабатывать в браузере на заглушках: `cd frontend && pnpm dev`, затем `http://localhost:3118/?mock=full`.
- Сценарии: `full`, `long`, `empty`, `recording`, `error`, `onboarding` (`docs/case/mock.md`). Сценарии итога записи: [ui/recording-outcome.md](ui/recording-outcome.md#заглушки-для-разработки).

## Проверка в окне приложения
- Визуальные задачи (анимации, размытие, стекло, уведомления) в конце проверять в окне приложения: оно рисует WebKit, а заглушки обычно смотрят в Chromium, и `backdrop-filter`, `filter: blur` и их анимации в WebKit ведут себя иначе.
- Самый дешёвый путь: если `tauri dev` уже запущен, подменить dev-сервер на порту 3118 сервером из нужной ветки и перезагрузить окно, Rust не пересобирается. После проверки вернуть сервер, как был.
- Данные в окне настоящие: создавать и удалять только свои тестовые встречи, удалённое возвращать, в отчёте назвать, что осталось.

## Сборка Rust
- `pnpm tauri:dev` с нуля и `tauri build` запускать только когда без них не проверить: тяжело и долго.
- Кеш сборки общий у рабочих деревьев через `CARGO_TARGET_DIR` основной папки.

## Проверки
- После правок во `frontend`: `npx tsc --noEmit`, `pnpm check:contrast`, `pnpm test`, `pnpm build`. Те же шаги на каждый PR в `shade` запускает `.github/workflows/shade-check.yml`.
- Скрипт переноса данных `scripts/migrate-from-aid.sh`: тест `bash scripts/test-migrate-from-aid.sh` (подставной `HOME`, вымышленные данные), в CI отдельной задачей той же проверки.

## Git и отчёты
- Не коммитить и не пушить без просьбы. Не пушить в `main`. PR не сливать самому.
- Без резервных копий файлов (`*-backup.tsx` и подобных): история есть в git.
- Отчёт о работе писать в описание PR по шаблону `.github/pull_request_template.md`. Файлы-самоотчёты (`*_DONE.md`, `*_REPORT.md` и подобные) не создавать.
- В `docs/case` только `mock.md`, `journal.md`, `metrics.md`, `decisions.md`.

## Вольт подробно
- Перед работой прочитать `00 NOW.md` (этап, следующий шаг, блокеры), файл проекта в `projects/` и правила `03 RULES.md`.
- После крупного шага обновить `00 NOW.md` и дописать `log/YYYY-MM-DD.md` (атомарно: временный файл, затем переименование). Решения добавлять строкой в `02 DECISIONS.md`.
- Если вольт недоступен (облачная сессия claude.ai/code): работать строго по промпту задачи, в ветке, сдавать pull request, отчёт (файлы, проверки, скриншоты, что не удалось) писать в описание PR, не сливать.
