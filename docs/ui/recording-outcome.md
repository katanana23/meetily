# Итог записи и корзина

Читать перед любой правкой того, что происходит после «Остановить»: отбраковка пустых записей, проверка моделью, карточка итога, корзина, удаление. Это логика с данными: действуют правила «Готово значит» и «Логика» из CLAUDE.md. Перенесено из CLAUDE.md. Пути от `frontend/src/shade/`.

## Три слоя против пустых записей
Пороги и сроки только в `lib/discard-policy.ts`: `EMPTY_MAX_WORDS`, `CHECK_MAX_WORDS`, `COUNTING_RUN`, `MODEL_CHECK_TIMEOUT_MS`, `TRASH_TTL_DAYS`. Ниже они названы по имени, значения смотреть в файле. Слои применяются только к новой записи при «Остановить»: встречи в базе и импорт не трогают.

### 1. Правила (`lib/content-rules.ts`)
Чистая функция, тесты `pnpm test` (это `bun test src/shade`).
- Считаются уникальные значимые слова.
- Не значимы: галлюцинации на тишине (`isHallucination`, `HALLUCINATIONS` в `lib/speech.ts`); междометия и заполнители («э», «ну», «да», «ага», «угу», «um», «okay»); проверочные фразы («раз-раз», «проверка», «алло», «слышно меня», «тест»); счёт от `COUNTING_RUN` числительных подряд (и через границу реплик); реплика из одного повторённого слова. Числа и даты вне счёта значимы.
- Значимых не больше `EMPTY_MAX_WORDS`: не сохраняется. От `EMPTY_MAX_WORDS + 1` до `CHECK_MAX_WORDS`: сохраняется и уходит на проверку моделью. Больше `CHECK_MAX_WORDS`: обычное сохранение.
- Значимых не больше `EMPTY_MAX_WORDS`, а детектор слышал речь: сначала ждём пустую очередь распознавания.
- Не сохранена: встреча не создаётся и строки в списке нет. Карточка по контексту:
  - «Пустая запись - не сохранена» (одной строкой, уходит сама через `EMPTY_NOTICE_MS` в `lib/recording-outcome.tsx`);
  - слов нет, детектор не сработал, запись не короче `SHORT_EMPTY_SECONDS` (`lib/speech.ts`): «Речи не было» и «Проверить звук»;
  - детектор слышал речь, текста нет по явной причине (нет модели, сбой распознавания): «Речь не распознана» (файл звука остаётся в папке записей).

### 2. Проверка моделью (`lib/content-check.ts`)
Только для диапазона «на проверку» из слоя 1.
- Вопрос идёт параллельно с сохранением, встреча стоит в списке как обычно.
- Модель итогов из настроек оригинала (`configService.getModelConfig`), ответ да/нет.
- Спрашиваем только Ollama (`/api/generate`, адрес из настроек, по умолчанию `DEFAULT_OLLAMA`, он разрешён в CSP). Встроенной модели (`builtin-ai`) короткий вопрос не задать без изменения ядра: она доступна только через `api_process_transcript`, который пишет итоги в базу. Облачным текст без спроса не отправляем. Для них ответ «недоступна».
- «Нет»: встреча в корзину (`trashMeeting`), и на месте «Встреча сохранена» карточка «Мало содержания» / «Запись в корзине» с «Вернуть» (во время новой записи то же тостом).
- Недоступна, ошибка или нет ответа за `MODEL_CHECK_TIMEOUT_MS`: встреча остаётся.
- Раздела и фильтра «Не распознано» нет: все встречи в одном списке.

### 3. Корзина (`lib/meeting-trash.ts`, `lib/recording-trash.ts`)
Для удалённого человеком и убранного проверкой моделью.
- Удаление встречи переносит папку записи в корзину (`TRASH_DIR_NAME`) с меткой `trashed.json` (id встречи, прежний путь, название, дата). Метка источник правды. `shade.meetingTrash.v1` в localStorage только кеш (свой у dev и собранного приложения), при запуске сверяется с метками.
- После удаления уведомление с «Вернуть».
- `TRASH_TTL_DAYS` дней можно «Восстановить» из фильтра «Корзина» (папка на место, транскрипт и итоги целы); у строки подпись «Удалится через N дн.». Там же «Удалить насовсем» и «Очистить корзину» с подтверждением.
- Срок проверяется при запуске и раз в `TRASH_PURGE_EVERY_MS` (`lib/recording-outcome.tsx`). В текстах срок подставляется из константы (`tDays`, `{days}` в `strings.ts`).
- Кнопки «Открыть корзину» (папка в Finder) нет: корзина управляется только в приложении.
- Окончательное удаление (по сроку или вручную) в одном месте: строка базы и папка по одной метке, `trackMeetingDeleted` только тогда.
- Папку не перенести: пометка только в кеше, в корзине подпись «Файл записи остался в папке».

## После «Остановить»
- Экрана обработки нет: главная сразу показывает список встреч (`lib/recording-controls.tsx`: вид `list`, `finish`).
- Новая встреча первой строкой в «Сегодня» (`PendingRow` в `components/MeetingRow.tsx`): миниатюра со спиннером, время и шаг. Когда встреча сохранится и список перечитается, на её месте обычная строка.
- На месте кнопки записи одна карточка (`FinishCard`, общий `Notice`), которая меняет состояние на месте, без мигания и одной ширины:
  «Дописываю реплики» (STOPPING и PROCESSING_TRANSCRIPTS, ожидание последних фраз) → «Сохраняю» (SAVING) → «Встреча сохранена» с «Открыть» и крестиком (уходит сама через `SAVED_CARD_MS`, под курсором и в фокусе ждёт, Esc закрывает); подписью название встречи.
- Запись отбракована: строки нет, та же карточка: мало значимых слов «Пустая запись - не сохранена» одной строкой; длинная без речи «Речи не было» и «Запись не сохранена» с «Проверить звук»; речь слышна, текста нет по явной причине «Речь не распознана».
- Проверка моделью убрала встречу в корзину: «Встреча сохранена» сменяется на месте карточкой «Мало содержания» / «Запись в корзине» с «Вернуть».
- В круге 44 px показ процесса (`FinishGlyph`, `.shade-fg-*`): три полосы волны записи дышат, на «Сохраняю» поворачиваются в строки текста, на «Сохранена» строки гаснут и появляется галочка, у отбракованной полосы опадают в точки. Только `transform` и `opacity`; при «уменьшить движение» статичный знак шага.
- Логотип и плитки с длительностью, словами и репликами здесь не показываются.
- Переход оригинала к встрече после сохранения (`?source=recording`) пропускается на любой странице (`lib/in-place-router.tsx`): встречу открывает «Открыть».

## Заглушки для разработки
- Карточка шага: `?mock=full&finish=transcribing|saving|saved|discarded`.
- Уведомления: `?notice=empty|no-speech|unrecognized|low-content`.
- Исход проверки моделью: `&check=content|empty|unavailable|timeout`.
- Весь путь: `?mock=words-20`, `budget-9&check=empty`, `counting`, `mic-check` или `silence-5s` и «Остановить».
